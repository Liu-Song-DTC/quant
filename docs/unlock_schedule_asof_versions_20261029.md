# 解禁日程按观测版本回放

组合过滤 `exclude_unlock_periods=true` 会查询未来 30 天内解禁规模是否 ≥5%。原 `get_unlock_codes()` 对历史决策日直接读当前 `unlock_schedule.pkl`，而 `load_unlock()` 又每天从 2021 年全史重新下载、覆盖整张表。2026-09-02 的旧表与 2026-10-29 的现表对照：旧表独有 206 条解禁记录，其中 60 条曾达到 5% 过滤阈值；相同键的数值也有修订。它们对历史候选集合有影响，不能凭最新表声称当时已经知道。

`unlock_schedule_versions.json` 记录每天实际观测到的文件 SHA-256，`unlock_versions/<sha>.pkl` 保存相应的不可变内容；实盘刷新每次更新解禁表后立即追加当日版本。选股按决策日期读取此前最近版本；在首版之前固定使用首版作为**可复现的历史代理**，不能解释成公告日严格 PIT。如果归档缺失/损坏，组合过滤及实盘新鲜度检查会拒绝继续。实验溯源还将版本清单纳入输入指纹。

首版于 2026-10-29 从此前发布的 `unlock_schedule.pkl` 只读复制，文件修改日期是 **2026-10-28**，据此记作 10-28 观测状态。这仅是现有数据态记录，不证明表中每条解禁计划早在 2021—2026 年历史决策日就已披露。回放比对 2021-01 至 2026-10-28 共 1,408 个行情日，首版代理相对本次修改前的当前表过滤集合**零差异**；未来版本的真实回测影响需要在数据刷新后固定快照配对验证。完整财报/解禁公告 PIT 和不可成交权益改善仍未证实。

监控口径：`histcells.py` 将供应商当前整表列为可重述层，继续逐格报告差异；归档表的读取校验摘要、最新发布表与最新归档一致性由 `check_unlock_versions` 硬闸负责。同日重抓若归档内容改变，选股缓存按归档路径失效，不再沿用旧集合。跨机器复现必须连同 `unlock_schedule_versions.json` 与 `unlock_versions/` 归档文件一起保存与迁移。
