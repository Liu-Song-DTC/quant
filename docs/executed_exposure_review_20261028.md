# 回测实际仓位与目标仓位口径核对（2026-10-28）

问题：旧`regime_state.csv`把`PortfolioConstructor`在调仓前计算的目标账簿市值除以权益，命名为`exposure`；`n_pos`也是目标账簿持仓数。向量执行器随后会根据真实可用现金缩放买入并按可成交开盘价买卖。因此这些字段不代表实际成交后资产暴露。封存对照里目标暴露有72天超过100%，最高149.73%，不能据此推断实盘使用杠杆。

`strategy/analysis/audit_executed_exposure.py`从封存的2,343笔实际模拟成交回报独立重放股数和现金，每日以封存复权价估值，与1,405日净值最大相差0.02175元（价格矩阵float32与文件CSV舍入）。现金最低1,833.80元、实际仓位最大99.71%、实际杠杆天数0。目标149.73%的2025-06-05，实际89.73%、实际6只而目标8只。对照文件：`.review_runs/actual_exposure_audit_20261028/report.json`及`daily.csv`。

报表修复：从向量执行器每个交易日成交后已计算的`positions`、`pos_value`、`nav`记录实际`exposure`/`n_pos`，原目标作为`target_exposure`/`target_n_pos`单独保存；记录数量不一致或不允许的实际杠杆会报错，报表写入失败也中止归档。没有修改组合决策、成交模型或每日净值。已用含目标149.7%而真实暴露89.7%的独立样例，以及改坏逐日净值的回放测试验证；正式端到端回测的输出报表须在下一次完整封存运行再验。此修复改变`regime_state.csv`字节内容，不能把报表字节差异算作策略收益漂移。
