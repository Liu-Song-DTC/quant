# 历史格哨兵刷新闭环

此前 `histcells.py snap` 即使部分文件读失败，也会把缺失摘要写为当日基线并返回成功；`diff` 同样忽略扫描错误。每日校验段仅识别历史格改写的退出码 2，其他失败也会继续出单，并用同名快照直接覆盖，进程中断可能留下半截 pickle。下一次对比可能据此误判历史未改变。

现在扫描或反序列化失败时校验段停止出单，不再发布新基线；写新快照使用同目录临时文件、刷新落盘后原子替换。确实发现历史格改写仍保持原有退出码 2 与告警流程，以便按既有供应商重述处置规则登记。三项隔离测试覆盖读失败、序列化中断与 diff 扫描失败；完整生产刷新和大基线实际滚存尚待验证。
