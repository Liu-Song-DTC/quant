3. 结果至少报：起始/最终权益、年化收益、Sharpe、全期与年度最大回撤和回撤起止、年度收益、已平仓**扣费用**胜率/笔数、真正入场后 1/3/5/10 日可执行或净标记胜率及笔数、固定槽位净收益和覆盖、无法成交率、换手及费用、最大单票/行业风险、典型败笔和缺数据样本。明确区分“信号价标记”“真实可卖的账面收益”“实际已成交现金流”。逐日权益、信号、选股、成交、持仓和风控状态均留档并对账。
4. 在动候选模型前写清主指标及约束：优先稳健的扣成本 3/5 日短期有效选股及覆盖；同时要求权益和回撤、尾部损失不能出现不可接受的倒退。样本少时同时报告置信区间与逐年分布，不靠筛掉难交易股票、空仓、事后补位或挑单一年份虚增条件胜率。收益与回撤、胜率常有取舍，任何版本未达到全部目标都明示，不包装成全面升级。2021–2026 已被多次研究，必须新增未来前推/固定留出验证，不能叫它“未使用的样本外”。
5. 保持实盘和回测同一数据可用时点、特征计算、股票池过滤、评分、目标持仓及订单生成路径；差异集中在撮合与真实券商回报，用接口契约单独验证。订单未成交/涨跌停/停牌/T+1/100 股/价格涨跌幅/费用/分红到账都须体现在绩效解释里。测试工程修复时要求原始权益/成交逐字节相同，若不相同必须拆分归因。
6. 每小项交付：问题与成因、最小代码差异、回归测试、同输入探针、是否改变信号/成交、结果链接与失败模式、可回滚提交。通过后按相关文件精确暂存并提交/推送；未验证的行为实验留在独立分支或工作树。由我最终复核输入指纹、代码差异、对照公平性、指标定义和生产一致性后再判断是否采纳。

## 4. 独立复核者接手时的检查顺序

逐提交检查工作区是否被误暂存、数据快照是否被写、源码与配置差异是否单变量；抽查时间线上的一笔原始行情、一个公司行动、一个公告/预告、一个市场特征、一个 ML 训练预测日、一个信号和一笔买卖，独立重算到账本。复算封存对照/候选的 SHA256、费用和胜率分母，并按年度及 2026 回撤区间看收益来源；检查失败对照是否被如实报告。只有保证数据身份、实盘时间可用性、真实可成交及扣成本评价后，才决定纳入工程修复或策略改进。未经证实的收益提升保留实验分支。

评审交付格式：`问题 → 证据路径/版本 → 最小修改 → 单测与数据探针 → 同快照全量对照（含失败项） → 实盘一致性检查 → 可回滚提交/推送状态 → 剩余风险`。审查期间不要把目标“必须提高收益”理解为可以针对已看过的年份反向调参；如没有稳健胜出的候选，交付可信的系统和明确负结果。

## 6. 全代码审查的执行清单与交接门槛

受历史策略文件体量和供应商时点证据限制，后续评审采用**每条真实生产路径及每一类数据字段的逐项清单**，避免“只检查热门文件”或空泛地宣称逐行无错。实施者交付 `source_inventory.csv`（相对路径、Git 跟踪状态、执行入口/调用者、依赖数据、配置项、缓存键、输入时点、失败语义、对应测试、证据文件、审查人），各层完成一栏才算覆盖。按目录逐项评审：

1. 数据：源接口与证券身份、并发下载和重试结果、裸 K 线与指数、元数据及 ST、事件合并与复权锚、财报各季度版本、另类/概念/宏观、数据版本快照和失败恢复。
2. 因子：每个原始列及衍生项的单位、方向/截断/饱和、是否被配置实际消费、股票池掩码与中性化先后、缺失含义、跨日期缓存与历史发布日期；把“白名单声明的 62 个”和“真实进入的 30 个基础列”分开统计。
3. ML 与评分：标签与可执行买卖日、训练/验证/校准/测试边界、32 项未进入因子表的白名单、模型元数据及缺特征、分窗口特征重要性、预测覆盖、不同目标/融合权重、跨周期 IC 和头部选股净收益。
4. 组合与执行：实际候选→持仓与价格、现金规模/仓位与行业限额、停牌与涨跌停、T+1/新股、浮动成本、发生过与未发生的订单、真实券商回报对账、每日权益及压力回撤；测试 2026 段尾部亏损，不只看全期夏普。
5. 性能与运维：缓存失效、重复扫描和读文件、并发资源、异常恢复和原子发布、每日链监控、版本/日志留存；每项性能改动需要信号及成交不变性对照。

实施和独立复核互不共用“已经成功”的口头结论。审查者逐包给出 `confirmed / refuted / unknown` 和证据；未确认项留待办，失败项保留负结果，不为凑高收益修改门槛。第一批最值得实施的顺序更新为：**(1) 新上市股票下载缺口与真实上市集对账 → (2) 工作区/已提交版本隔离与生产门禁恢复 → (3) 同一源码快照下复算真实仓位报告 → (4) 历史概念信息边界和财报时点 → (5) 因子饱和与 ML 缺失状态 → (6) 组合/执行成本及未来前推实验。**

本轮只对计划和隔离探针做验证，没有刷新生产数据或新跑完整回测。已执行 `strategy.tests.test_signal_input_identity`、`test_ml_signal_validity`、`test_regime_reporting`、`test_qfq_event_audit` 共 **10 项单测，全部通过**；此外，独立临时目录的“仅有指数文件”新鲜度检查返回通过，用于证明**应有证券集合对账缺失**。既有单测通过不抵消该新发现，新增缺股门禁测试是 P0 首项交付。
