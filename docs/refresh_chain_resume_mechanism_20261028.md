# 刷新链"可重入"机制 (2026-10-28)

解决的具体浪费：**校验段失败后重跑链 ⇒ 5,394 只被再下一遍(约 50 分钟)。**
10-28 实测：18:29 刷新**成功**（数据到 10-28）→ 20:45 新鲜度门禁因两只停止交易的股票
拦停 → 21:11 重跑整条链 = 白等 50 分钟（而且那次还撞上上游代理不通）。

## 1. 机制（4 件）

### 1.1 取数段 / 校验段分离

| 脚本 | 内容 |
|---|---|
| `data/refresh_fetch.sh` | 步骤 1-8：K线下载 → 事件表 → 表驱动复权重建 → 守卫(1b/3b/3c) → 基本面 → 另类 → 概念 → 转债 |
| `data/refresh_verify.sh` | 新鲜度门禁 + 历史格哨兵（打新提醒不再自动运行） |
| `data/refresh_all.sh` | **兼容入口** = fetch && verify（对外调用方式不变） |
| `strategy/run_daily_live.sh` | 第 1 步改为**两次调用**（fetch / verify）⇒ 校验失败可只重跑校验段 |

### 1.2 取数幂等标记（`stock_metadata/kline_sync_<MMDD>.stamp`）

标记内容 = `{名册文件 sha256, synced_through(目标交易日), listed, at}`。

下载器判据放在**任何网络调用之前**（关键）：名册文件 sha 未变 **且** 已同步到**同一个目标
交易日** ⇒ 跳过下载。放在网络之前是因为上游/代理抽风时（10-28 21:00 实测鉴权失败）
也必须能跳过，否则"重跑"又变成一次 50 分钟的下载尝试。

- 失效条件：跨日（目标交易日变）/ 名册内容变 / `QUANT_FORCE_FETCH=1` / `--full`
- 取舍：同日跳过**不重查 EM 侧复权重锚**（同交易日内上游不会改已收盘的历史）；
  跨日必取 ⇒ 10-17/10-23 那类"上游重锚历史"的检出能力不变

### 1.3 链级断点（`logs/.chain_state_<date>`）

记录 `refresh / signals / navlaw / orders` 四个完成标记；重跑链时若本日 `refresh` 已完成
⇒ 跳过取数段（`--fresh` 强制重取）。信号段不另设断点：`bt_execution.py` 自己的
**内容指纹复用闸**（输入字节 + 代码内容摘要）负责判"信号可否复用"，这比链级标记更严。

### 1.4 门禁自动提名（消除"人工考古"）

`check_data_freshness.check_kline()` 发现滞后码时：若该码**已不在上游在册名册** ⇒ 它是
"停止交易(退市/长期停牌)" ⇒ 无后续K线是真实状态 ⇒ 自动生成可直接粘贴的滞后白名单建议行，
写入 `data/stock_data/kline_stale_proposals.txt`，并把建议行带进门禁失败信息。
仍在册的滞后码**不提名**（那是真数据问题，必须硬失败）。

## 2. 实测

| 场景 | 改前 | 改后 |
|---|---|---|
| 同日重跑（取数段） | 5,394 次网络往返，约 50 分钟 | **1.7 秒**（幂等标记命中，且不碰网络） |
| 校验段失败后重跑 | 整链重跑（50 分钟取数 + 80 分钟信号） | 只重跑校验段（秒级）+ 信号段（必要成本） |
| 门禁因退市股拦停 | 需人工查名册/末bar 才能知道登记什么 | 门禁直接给出建议行（实测 `002827 高争民爆 2026-10-23 …`） |

## 3. 剩余风险 / 后续

1. 取数段里**除下载外**的步骤（事件表 ~5min、复权重建 ~10min、另类/概念 ~20min）在
   同日重跑时仍会重做 ⇒ 后续可给它们也加"输入身份"标记（重建的输入身份 = 事件表 sha256
   + raw 目录摘要；概念的输入身份 = 概念映射版本表）。
2. 同日跳过下载 ⇒ 不做 EM 复权重锚检查（见 1.2 取舍）。
3. 链级断点只覆盖取数段；信号段依赖 `bt_execution` 的内容指纹闸（更严，但它是**产物复用**
   闸，不是"步骤完成"闸 ⇒ 两者语义不同，不要混用）。
4. `refresh_fetch.sh` / `refresh_verify.sh` 拆分后，**外部调用方**若只调
   `refresh_verify.sh` 而没先跑 fetch，门禁会按"上一交易日"口径判 ⇒ 报错可读。
