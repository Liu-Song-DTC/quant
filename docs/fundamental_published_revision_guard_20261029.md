# 基本面旧报告回修门禁

生产刷新 `data/refresh_fetch.sh` 的第 4 步调用 `data/refresh_fundamental_recent.py`。该程序现在先合并三个已过法定披露截止日的报告期源表，再逐只比对已发布单股文件中同报告期、同字段的值；任何历史修订在写入单股文件**之前**中止整批刷新，生成 `data/stock_data/stock_metadata/fundamental_revisions_*.json` 取证。新出现的报告期允许追加。输入源表的可用日也在写入前验证。通过预检之后，原有的全库可用日检查仍继续运行。

先前某个报告期的四张源表缺失时，刷新会跳过这一期却返回成功；现在缺任一期即返回非零，不再把旧季度资料当成已刷新。
若合并后 CSV 与已发布文件逐字一致，直接跳过该股文件写入，减少整池重复落盘和文件时间戳变化；实际需要追加新季度的文件仍使用临时文件加原子替换。

只读探针（不下载、不写单股基本面）：

```bash
.venv/bin/python -B data/refresh_fundamental_recent.py --no-download --preflight-only
```

2026-10-29 使用现有三个报告期的源文件比对已发布数据：5,565 只股票的 16,690 条重叠报告记录，未见字段变化。四张报表中业绩快报名单与资产负债表名单存在数百条差异，抽查 `20260630` 缺失资产负债表的 344 条业绩快报名单均不在当前行情池内；不据此推断所有报表完整或实际公告日期正确。

限制：本门禁只防止此前**已写入**报告期发生无记录的数值回修。尚不能证明供应商记录等于当时的公告版本，也不能把法定截止日代理当成真实发布日期。刷新过程中若在预检通过后外部程序同时改写源表，仍须用数据快照与锁解决；单股文件目前逐个原子写入，并不是整个基本面目录的一次事务提交。
