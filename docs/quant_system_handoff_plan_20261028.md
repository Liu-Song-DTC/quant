3. 结果至少报：起始/最终权益、年化收益、Sharpe、全期与年度最大回撤和回撤起止、年度收益、已平仓**扣费用**胜率/笔数、真正入场后 1/3/5/10 日可执行或净标记胜率及笔数、固定槽位净收益和覆盖、无法成交率、换手及费用、最大单票/行业风险、典型败笔和缺数据样本。明确区分“信号价标记”“真实可卖的账面收益”“实际已成交现金流”。逐日权益、信号、选股、成交、持仓和风控状态均留档并对账。
4. 在动候选模型前写清主指标及约束：优先稳健的扣成本 3/5 日短期有效选股及覆盖；同时要求权益和回撤、尾部损失不能出现不可接受的倒退。样本少时同时报告置信区间与逐年分布，不靠筛掉难交易股票、空仓、事后补位或挑单一年份虚增条件胜率。收益与回撤、胜率常有取舍，任何版本未达到全部目标都明示，不包装成全面升级。2021–2026 已被多次研究，必须新增未来前推/固定留出验证，不能叫它“未使用的样本外”。
5. 保持实盘和回测同一数据可用时点、特征计算、股票池过滤、评分、目标持仓及订单生成路径；差异集中在撮合与真实券商回报，用接口契约单独验证。订单未成交/涨跌停/停牌/T+1/100 股/价格涨跌幅/费用/分红到账都须体现在绩效解释里。测试工程修复时要求原始权益/成交逐字节相同，若不相同必须拆分归因。
6. 每小项交付：问题与成因、最小代码差异、回归测试、同输入探针、是否改变信号/成交、结果链接与失败模式、可回滚提交。通过后按相关文件精确暂存并提交/推送；未验证的行为实验留在独立分支或工作树。由我最终复核输入指纹、代码差异、对照公平性、指标定义和生产一致性后再判断是否采纳。

3. **从真实数据可用时点做特征审计。** 先列出每个特征的文件、生成规则、日期/时间戳、是否已进入 ML/线性评分、历史缺失比例、相关性及缺失应如何拒绝或表示。优先研究公告后真实可用的财报边际/预告、行业成交额份额与广度；美债收益率、人民币汇率、全市场波动率先做无前视预警探针。用户建议的政策→行业→资金链条是研究假设，不能仅凭故事声称“领先价格”。

## 4. 独立复核者接手时的检查顺序

逐提交检查工作区是否被误暂存、数据快照是否被写、源码与配置差异是否单变量；抽查时间线上的一笔原始行情、一个公司行动、一个公告/预告、一个市场特征、一个 ML 训练预测日、一个信号和一笔买卖，独立重算到账本。复算封存对照/候选的 SHA256、费用和胜率分母，并按年度及 2026 回撤区间看收益来源；检查失败对照是否被如实报告。只有保证数据身份、实盘时间可用性、真实可成交及扣成本评价后，才决定纳入工程修复或策略改进。未经证实的收益提升保留实验分支。

评审交付格式：`问题 → 证据路径/版本 → 最小修改 → 单测与数据探针 → 同快照全量对照（含失败项） → 实盘一致性检查 → 可回滚提交/推送状态 → 剩余风险`。审查期间不要把目标“必须提高收益”理解为可以针对已看过的年份反向调参；如没有稳健胜出的候选，交付可信的系统和明确负结果。
