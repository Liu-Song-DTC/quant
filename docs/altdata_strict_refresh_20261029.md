# 另类数据生产刷新：拒绝以旧缓存伪装成功

生产链 `data/refresh_altdata_0902.py` 此前通过非空返回值判断刷新成功；`load_reduction()` 捕获下载异常后会返回已有的非空 `reduction_records.pkl`，`load_reduction_plans()` 捕获异常后也会返回旧计划，且逐月获取计划时会跳过失败月份。两张表都可参与组合过滤，旧缓存冒充当日刷新会让新公告静默缺席。

专用刷新任务现在创建 `AlternativeDataProvider(strict_refresh=True)`：减持记录下载异常会重新抛出；减持计划任一月份下载异常停止整个任务，不写部分月份并拒绝用旧表充数。`refresh_altdata_0902.py` 收集失败并以非零状态退出；回测与信号读取默认行为不变。零条新增公告本身仍可能合法，因此未将空增量视为网络失败；这项源头真实性需再用独立公告源或接口状态验证。

两个隔离测试模拟断网和已有非空缓存，验证生产刷新报错、旧缓存文件字节不变，同时验证普通读取的兼容行为。此修改不改变任何已保存行情、因子或回测输入；生产网络刷新全链与完整回测仍需另行验证。
