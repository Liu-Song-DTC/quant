# ML分段缓存复现审计（2026-10-27）

## 已确认的缺口

上层信号和原始因子缓存已有内容身份，ML分段缓存仍有独立依赖链：`_ml_chunk_cache_aux_fp`以基本面/题材文件的mtime和大小判断变化，未纳入版本化概念成分历史；K线前缀指纹未绑定证券身份、CSV表头及独立指数历史。`_ml_chunk_save`注释称预测原子写入，实际直接写Parquet；加载不核对预测文件内容。

因此保留大小和mtime的历史重写可能继续命中旧ML预测，上层重新生成信号也不足以消除此问题。这是机制层面的复现缺陷，不是已证明某次收益下降的唯一原因。

## 修复与边界

- 基本面、元数据、题材、版本化概念成分按逻辑角色与内容SHA256识别，记录ML相关配置、代码指纹及Python/NumPy/pandas/XGBoost版本。跨目录相同输入不因路径或mtime改变而失效。
- K线仍按每段预测结束日期切分，追加未来行情不改变旧段；加入股票代码角色、表头和三个市场指数的历史前缀，必需的个股文件无法读取时拒绝构造身份。
- 预测Parquet先原子写入，再保存模型，最后发布清单；清单保存预测内容SHA256和格式版本。加载时核验字节、字段、唯一键、有限预测及训练成功段的模型引用。旧无证据格式按未命中处理。
- 模型成员完整性继续由`MLFactorPredictor.load_model`的全成员读取与已有校验负责；缺任一成员整段退回重训。

旧缓存将失效，第一次需要重新训练。这项改动修复缓存复用边界，不改标签、参数、融合权重或选股门槛。当前完整ML覆盖实验使用先前封存代码，未中途替换。

## 验证

`test_ml_chunk_identity`共5项：保留mtime的财报/概念成分改写、未来K线追加与证券/表头/指数变更、跨目录内容一致、预测篡改与中断写入、真实三成员模型往返及成员缺失。连同模型预处理和通用内容身份共11项测试通过。

测试使用临时输入与真实小模型，不等于完整生产缓存热/冷两遍净值已验证。其他缓存和外部数据链仍需逐项审计，不宣称全项目已无漂移。
